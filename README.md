# Dead Dispatch

> A haunted postal sorting office. Tap, route, stamp, and survive 60–90 second shifts. Restore the building one floor at a time.

Hybrid-casual puzzle + light management game built with **Flutter + Flame**. Android first, structured for iOS.

## Quick start

This repo contains the application source. The Flutter platform folders (`android/`, `ios/`, `web/`, etc.) are not committed — they're generated by `flutter create` so they pin to your local Flutter toolchain.

```bash
# 1. From the repo root, materialize platform folders (one time per machine)
flutter create --org com.deaddispatch --project-name dead_dispatch --platforms=android,ios .

# 2. Install dependencies
flutter pub get

# 3. Run on a connected Android device or emulator
flutter run

# 4. Run tests
flutter test

# 5. Release build (Android)
bash scripts/build_release_android.sh
```

> The bundled `pubspec.yaml`, `lib/`, `assets/`, and `test/` are authoritative. Platform folders that `flutter create` produces should be left alone unless you intentionally edit Gradle, AndroidManifest, Info.plist, etc.

## Architecture

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). TL;DR layers:

```
core   →  cross-cutting primitives (logger, env, failures, perf)
domain →  pure Dart models + services (no Flutter, no Flame)
data   →  repositories, local storage, JSON config loading, save migration
services → platform integrations (ads, analytics, audio, haptics) behind interfaces
game   →  Flame world, components, systems
presentation → Flutter screens/widgets/theme
di     →  Riverpod providers wiring it all together
```

Domain has zero Flutter or Flame imports — that's the rule that keeps the game testable.

## Balancing

All tunable numbers live in [assets/config/](assets/config/) as JSON. See [docs/BALANCING.md](docs/BALANCING.md).

## Monetization

Rewarded ads only. Placements: continue-after-fail, double rewards, mystery parcel, instant repair. The default `AdsService` implementation is a stub that always grants the reward — swap in AdMob without touching domain code.

## Contributing

- Run `flutter analyze` and `flutter test` before each commit.
- Don't put balancing numbers in code — put them in `assets/config/`.
- Keep `domain/` free of Flutter and Flame imports.
